# DECISIONS.md

- **D1** Stack: React + TypeScript + Vite, Vitest, native HTML5 drag-and-drop — most standard stack, no DnD dependency needed for a simple vertical list. Approved deps only: react, react-dom, typescript, vite, @vitejs/plugin-react, vitest; anything else needs explicit approval. — 2026-07-03 (spec review)
- **D2** Persistence via localStorage auto-save on every change — spec omitted storage; simplest correct option for a single-user PWA; export/import is the backup path. — 2026-07-03 (spec review)
- **D3** History `day` = stored `currentDay` set by Start New Day, not wall-clock date at completion — working past midnight must not split a manual day's log. — 2026-07-03 (spec review)
- **D4** Start New Day auto-collapses Done into History under the old day before resetting Today — avoids stale strikethrough tasks lingering into the new day. — 2026-07-03 (user choice)
- **D5** Undo completion allowed (Done→Today; subtask un-tick) until cleared to History — protects against misclicks. — 2026-07-03 (user choice)
- **D6** Manual Today→Master removal allowed; day-copies are discarded on removal — fixes planning misclicks without waiting for Start New Day. — 2026-07-03 (user choice)
- **D7** Subtasks keep creation order, no drag reorder in MVP — not in spec, keeps scope down. — 2026-07-03 (spec review)
- **D8** History UI is a minimal read-only toggle panel grouped by day, newest first — spec defined History data but no display. — 2026-07-03 (spec review)
- **D9** Day-copies get `isRecurring: false`; provenance lives in `sourceTaskId` — the copy is an ordinary Today task, keeps sorting and deletion rules simple. — 2026-07-03 (spec review)
- **D10** Architecture: pure TypeScript core (state.ts et al.) with thin React shell — makes every spec rule unit-testable without a browser; suits red/green TDD. — 2026-07-03 (spec review)
- **D11** `completeTask` throws on open subtasks (rather than silently no-op) — the parent gate is a business-rule violation like an empty title, so a hard error is clearer; the UI also disables the Complete button as a first line of defence. — 2026-07-03 (slice 3)
- **D12** Subtask ops guard the "done never holds an open subtask" invariant by no-op: `addSubtask` and `uncompleteSubtask` do nothing on a Done parent (empty title still throws, matching D11's title rule) — keeps the model always valid; the undo flow is Done→Today first, then un-tick. — 2026-07-03 (slice 4) *(SPEC §6.4 amended 2026-07-04 to record this — it previously promised un-tick until cleared to History.)*
- **D13** `setActive`/`setActiveSubtask` toggle and are guarded by no-op (unknown id, or item not in Today) rather than throwing — activation is a benign UI gesture, not a business-rule violation like an empty title, so silent no-op is friendlier; single-active is enforced by clearing all flags before setting. — 2026-07-04 (slice 5)
- **D14** `removeFromToday` clears the returning task's active flags (task + subtasks); auto-clear on complete/delete falls out of existing code (own-flag clear / removal) — upholds the "active ⇒ in Today" invariant without extra plumbing. — 2026-07-04 (slice 5)
- **D15** `startNewDay` reuses `clearDone` for step 1 (before advancing `currentDay`, so Done logs under the old day) and `clearAllActiveFlags` for step 4 — no duplicate logic; the five ordered effects compose from existing pure functions. UI gates the button behind a `window.confirm` since discarding day-copies is irreversible. — 2026-07-04 (slice 6)
- **D16** Export uses a versioned envelope `{ schemaVersion, state }` rather than a bare AppState — a future incompatible shape change can be detected/migrated on import; `importState` validates the envelope and reuses `storage.isAppState` (exported to avoid a duplicate validator) so garbage throws a clear Error instead of crashing. — 2026-07-04 (slice 7)
- **D17** PWA is hand-rolled (no Vite PWA plugin, honouring D1): static `manifest.webmanifest` + generated 192/512 PNG icons + a minimal cache-first `sw.js` (precache shell, runtime-cache visited assets) registered in `main.tsx` — smallest correct install/offline path with zero new dependencies. — 2026-07-04 (slice 7)
- **D18** Subtask tick/un-tick is guarded to parents in Today (core no-op elsewhere; Master checkboxes disabled in UI) — a master task is a template, so ticking it polluted every future day-copy as pre-completed; SPEC §6.4 amended. — 2026-07-04 (post-slice-7 code review)
- **D19** Day-copies reset inherited subtask completion to open on creation — a fresh occurrence starts with all subtasks open; SPEC §6.3 amended. — 2026-07-04 (post-slice-7 code review)
- **D20** A completed subtask cannot be set active, and `completeTask` clears its subtasks' active flags — upholds "active ⇒ open item in Today" through the Done transition; SPEC §6.8 amended. — 2026-07-04 (post-slice-7 code review)
- **D21** `isAppState` validates element shapes (tasks, subtasks, history entries), `importState` requires `schemaVersion` exactly 1, and both load and import sanitise invalid active flags by clearing all — corrupt or hand-edited data now gets a clear error or a safe repair, never a crash. — 2026-07-04 (post-slice-7 code review)
- **D22** Service worker v2: navigations network-first (falling back to cache), install precaches the shell plus asset URLs extracted from index.html, hashed `/assets/` served cache-first, activate prunes assets no longer referenced; registration is production-only at `BASE_URL` — fixes first-visit offline, the stale-forever update pin, and the dev-server cache trap. — 2026-07-04 (post-slice-7 code review)
- **D23** Edit/Delete exposed in every column per SPEC §6.2, but outside Master the edit form offers title + due date only (no recurring toggle) — flipping a Today/Done task to recurring mid-flight would contradict day-copy semantics (D9). — 2026-07-04 (post-slice-7 code review)
- **D24** `clearActive` export removed as dead code — the un-set gesture is the toggle inside `setActive`/`setActiveSubtask`; no production caller existed. — 2026-07-04 (post-slice-7 code review)
- **D25** Relative due-date labels anchor on the wall-clock day (`useWallClockDay` in App.tsx), not `state.currentDay` — a due date's "today"/"tomorrow" should track the real calendar so labels stay correct when the app sits open past midnight without Start New Day. The header "Day:" and History logging (D3) keep using the manual `currentDay`; only the labels move. The hook re-syncs on a 60s interval plus visibility/focus changes to catch the midnight rollover on throttled background tabs. — 2026-07-08 (user request)
- **D26** A task title that is a bare URL renders as a tight clickable pill of just its domain (`parseUrl` in core/urls.ts, `TaskTitle` shared component) — a read-later list of pasted links stayed legible instead of full-width truncated rows. Only single-token http/https/`www.` titles with a real domain pill; anything with spaces stays prose. In Today the pill replaces the activate-toggle button, so URL tasks are set active via keyboard (space) rather than a title click. Subtask titles get the same treatment via the shared `UrlPill` (all three render paths: Done read-only, Today activatable, plain). — 2026-07-08 (user request)
- **D27** The Master add-task form is progressively disclosed: only the "New task…" field shows until the form gains focus (CSS `:focus-within`), then the due-date row unfolds — keeps the default UI to one line. The row is a single centre-aligned flex line (Due · quick chips · date · Recurring · Add) to kill the vertical zigzag. Added one-click relative due chips (Today / +1d / +7d) that toggle the date, computed from the wall-clock `today` via `addDaysISO`. — 2026-07-08 (user request)
- **D28** Due-date labels are colour-coded by urgency (`dueDateUrgency`): overdue (red) / today (amber) / soon ≤2 days (yellow) get a tinted pill, further-out stays muted; Done cards suppress the colour so completed items don't shout. Title bar (`.app__header` + theme-color meta) now tracks the light/dark theme via `--header-bg` instead of a fixed brand purple, so the in-app header and the PWA's OS title bar read as one bar. Task-card vertical padding tightened (0.6→0.3rem). — 2026-07-08 (user request)
- **D29** Reverted D28's manifest additions (`display_override`, `id`) — they were speculative hardening for "hide browser extensions" and added no real effect over the pre-existing `display: standalone`; dropped at user request. — 2026-07-08 (user request)
- **D30** Dropped the `.app__header` background + bottom border (and the now-unused `--header-bg` var) from D28 — the theme-aware `theme-color` meta already tints the OS title bar to match, so the extra in-app bar chrome was redundant; the header is transparent again over the body. — 2026-07-08 (user request)
- **D31** Cross-device sync (SPEC §12) is GitHub-gist-based rather than a custom backend — free, needs no server or account system beyond a GitHub personal access token the user already can create, and a private gist is a perfectly adequate single-file JSON store for one user's data. The whole `AppState` is stored as one envelope (`{ schemaVersion, modifiedAt, state }`) and reconciled by last-write-wins on `modifiedAt`, with a `window.confirm` prompt (same pattern as the existing Import/Start-New-Day confirms) whenever both the local device and the gist changed since the last sync — simplest correct behaviour for a single-user, few-device app; a real merge (e.g. per-task) was ruled out as unnecessary complexity for MVP. — 2026-07-09 (stage 2, UI integration)
- **D32** The GitHub token is stored in `localStorage` alongside the rest of app state (`core/gistSync.ts`'s `SyncConfig`), not in a more isolated store (e.g. IndexedDB, session-only memory) — accepted trade-off: anything that can read this origin's `localStorage` (e.g. an XSS bug elsewhere in the app) can read the token, but the app already has no such isolation for other data, token scope is limited to `gist` only, and the token never leaves the device except as an `Authorization` header to `api.github.com`. Disconnect clears the token from storage; it does not revoke it on GitHub (the user does that from GitHub's token settings if desired). — 2026-07-09 (stage 2, UI integration)
- **D33** Dirty-since-last-sync tracking lives in a dedicated `localStorage` flag (`todo-pwa/sync/dirty/v1`) rather than in React state — a debounced push can be in flight when the tab closes, and only a persisted flag lets the next load's reconcile still tell "local changed since last sync" apart from "device is pristine." Set synchronously on every local state change while connected (via `useGistSync`'s push-on-change effect) and cleared only after a successful push or a successful remote-apply. — 2026-07-09 (stage 2, UI integration)
- **D34** UI layer rebuilt on a "warm Bauhaus" visual direction (SPEC §13) — the previous interface was buggy and did not feel right; the pure core (`src/core/`) and its tests were kept untouched, so no data model, storage key, or business rule changed and existing `localStorage` data loads as-is. Type is Futura (Renner, 1927 — the Bauhaus face, present on macOS) with geometric fallbacks and no webfont, so nothing can silently fall back over the network. — 2026-07-24 (user request)
- **D35** The Master add form no longer progressively discloses its controls (reverses D27) — the `:focus-within` panel was the cause of the "first click does nothing" bug: submitting refocused the field, so the next click on a task first blurred the input, collapsed the panel, and shifted the list out from under the pointer. Every control now sits on one permanently-visible row of constant height, so focus changes can never reflow the list. — 2026-07-24 (user request)
- **D36** A due date can be typed as a trailing token in the task title (`core/taskInput.ts`): `today`/`tomorrow`, `mon`–`sun`, `+3d`/`+2w`, or an ISO date. Only the final whitespace-separated token is considered and only when a non-empty title remains, so "Review monday notes" is untouched; a trailing full stop ("Friday.") is the escape hatch for a literal date word. The resolved date is echoed live beside the field before submit, and a date picker remains for setting one without typing. Weekday tokens resolve to the nearest occurrence at or after today (typing "fri" on a Friday means today), matching the common convention. — 2026-07-24 (user request)
- **D37** A newly created task flashes for 1.6s (`task--flash`) — Master sorts by due date, so a new task lands mid-list rather than at the bottom and previously had to be hunted for. The id comes from computing `createTask` eagerly rather than inside a `setState` updater, so no side effect runs in a reducer. Adding while Master is collapsed also expands it, since the task would otherwise appear to vanish. The ochre left bar is outside the animation, so the marker survives `prefers-reduced-motion`. — 2026-07-24 (user request)
- **D38** All three columns collapse, vertically, through one shared `Column` shell, and the layout supplies the difference the user asked for: desktop is a three-track grid so a collapsed column keeps its horizontal slot (space reserved, neighbours never move), while below 900px the board is a single stacked track so collapsing frees vertical space and the columns below flow up to fill it. `align-content: start` stops the grid from redistributing that freed space back as a gap. — 2026-07-24 (user request)
- **D39** The separate mobile shell (swipe pager, action sheets, long-press reorder, undo toasts — `src/ui/mobile/`, `mobile.css`, `QuickAdd`, `useMediaQuery`) was removed in favour of the one responsive board. A horizontal pager cannot express "collapse a column and let the others fill the space" (D38), since only one column is ever on screen. Touch affordances are kept in CSS: `@media (hover: none)` keeps row actions permanently visible at a 2.4rem tap target and drops the drag handle, leaving the existing Move up/down buttons as the touch reorder path. Swipe gestures and undo toasts are gone and would need re-adding deliberately. — 2026-07-24 (user request)
- **D40** Row actions are absolutely positioned on hover-capable devices rather than holding a grid slot — occupying no layout space, they cannot reflow the row when revealed (the same anti-shift rule as D35), and titles get the full column width instead of losing ~9rem to permanently reserved buttons. On touch they stay in flow on their own grid row, always visible. — 2026-07-24 (slice: UI rebuild)
- **D41** All `localStorage` access goes through `core/safeStorage.ts`, which catches and reports instead of throwing — `setItem` throws on `QuotaExceededError` and throws on *every* call when the browser blocks site data, and the auto-save (D2) runs in an effect, so an unguarded throw propagated through React's commit phase and unmounted the whole tree (blank screen, on every subsequent change). Failures are reported to a single subscriber rather than swallowed: `App` renders a persistent warning band, because a to-do list that silently stops saving is worse than one that says so. `save()` now returns a boolean rather than `void`. — 2026-07-25 (code review)
- **D42** `deleteTask` cascades to any day-copies of the deleted task (`sourceTaskId === id`), reversing the earlier "a dangling reference is fine" position — it was not fine. `removeFromToday` reads `sourceTaskId` to choose between "discard this day-copy" and "return this task to Master", so an orphaned copy silently took the discard branch and the task disappeared with no route back. Delete means delete. — 2026-07-25 (code review)
- **D43** A recurring master can have at most one live day-copy in Today: `moveToToday` no-ops when `hasDayCopyInToday` is true, and the Master row disables its "Move to Today" button on the same condition so the no-op is never a mystery click. Two copies of one master are indistinguishable in the list — same title, same date, nothing to tell them apart or explain why there are two. Removing the copy (or a new day) frees the slot again; a copy in Done does not block a new one, since those two rows *are* distinguishable. — 2026-07-25 (code review)
- **D44** History is pruned to the last `HISTORY_RETENTION_DAYS` (30) by `pruneHistory`, called from `startNewDay`. Retention is measured against the newest day present in History, **not** the wall clock: History days come from the manual `currentDay` (D3), which can sit months behind real time, and anchoring on `new Date()` would treat entries logged seconds earlier as ancient and delete them immediately. Pruning runs on the explicit New Day action rather than on load, so the app never silently discards data at startup. — 2026-07-25 (user request)
- **D45** The manual light/dark toggle is wired up (`ui/useTheme.ts`, header button, `todo-pwa/theme/v1`). `styles.css` had carried `:root[data-theme='dark']` and `[data-theme='light']` since D34, but nothing ever set the attribute — the three-block sync rule was maintenance tax for a feature that did not exist. Preference cycles system → light → dark; `'system'` removes the attribute entirely so `prefers-color-scheme` governs again. — 2026-07-25 (user request)
- **D46** Modals trap Tab focus (`ui/useFocusTrap.ts`, used by `ConfirmDialog`, `SyncSettings`, `ShortcutHelp`). They already declared `aria-modal="true"`, which tells a screen reader the rest of the page is inert but does nothing about where Tab actually goes — focus walked out into the board behind the overlay. The hook re-queries focusable children on each Tab (dialog contents change) and wraps both directions. — 2026-07-25 (code review)
- **D47** ESLint added (amends D1's approved-dependency list: `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, all dev-only). The motivation is `react-hooks` specifically: a stale-dependency / ref-during-render bug in `useGistSync` is what let a development-only StrictMode effect re-run schedule spurious pushes to the user's real gist, and that class of mistake is invisible to both `tsc` and the core unit tests. The config is recommended rules only, no style opinions. Its first run found four real defects. — 2026-07-25 (user request)
- **D48** CI runs `npm run lint && npm test && npm run build`: gating the Pages deploy on `main`, and on every pull request via `.github/workflows/ci.yml`. Previously the deploy workflow ran only `npm run build`, so the 200+ core tests never ran anywhere but a developer's machine and a commit that broke a business rule shipped to production undetected. — 2026-07-25 (code review)
- **D49** A `SessionStart` hook (`.claude/hooks/session-start.sh`, registered in `.claude/settings.json`) installs dependencies for Claude Code on the web sessions. Those start from a clone with no `node_modules`, so the first `npm test` failed with `vitest: not found` and the session had to stop and install before it could verify anything. Guarded on `$CLAUDE_CODE_REMOTE` so local checkouts are untouched, and uses `npm install` rather than `npm ci` — the container image is cached after the hook completes, and `install` reuses an existing `node_modules` where `ci` always deletes and refetches. Left synchronous rather than async: it takes ~3s from cold, which is not worth the race where the agent runs the test suite while the install is still in flight. — 2026-07-25 (user request)
- **D50** History entries are editable and deletable in place (`updateHistoryEntry`, `deleteHistoryEntry`, `historyDeletionScope`; `HistoryPanel` rows, `ui/useLongPress.ts`) — the panel was read-only (SPEC §10 amended), so a task completed under a typo'd or wrong title was logged that way for 30 days with no way to fix it. **Title only:** `day`, `completedAt`, `occurrenceType` and the task-id links are the record of *when and what kind of* occurrence happened; offering those as fields would be rewriting the log rather than correcting it, and the title is the only field the panel shows. **Delete cascades** from a task entry to the subtask entries logged under it (matched on `parentTaskId` + `day`, so it cannot reach across days), because a subtask occurrence is never independent of its parent (SPEC §6.4) and orphaned children would sit indented under a parent that no longer exists — the same "delete means delete" position as D42. Delete confirms and names the collateral, since a History entry is the only remaining record of that occurrence; edit does not, being reversible by editing again. **Gesture:** a `<button>` per row so keyboard and screen readers get activation for free, with click on a mouse and a 500ms hold on touch (a tap is how you scroll past a row, so firing on tap would make the list unreadable; >10px of travel cancels the press so a scroll stays a scroll). Neither action restores a task to a column — this fixes the log, it does not undo a completion. — 2026-07-25 (user request)
- **D51** The board switched to a tap-first interaction model (`TaskEditPanel`, checkbox completion, undo toasts), replacing the floating action toolbar of D40 and re-adding the undo toasts D39 removed. **Inline edit:** tapping a Master/Today card body (`isEditTarget` in `cardKeys.ts` — a click that missed the card's own controls) opens one inline editor holding every per-card action: retitle (blank reverts), re-date, edit/add/delete subtasks (blanking a subtask input deletes it), delete, move between columns, and Today reorder. This retires the hover/`:focus-within` corner overlay (D40) and the title-only `TaskEditForm`; the panel keeps the mounted-only-while-editing convention so each field seeds fresh (bug C11). **Checkboxes, not buttons:** task completion is a checkbox in Today (checked ⇒ `completeTask`, disabled while subtasks are open so the D11 throw is never reached) and Done (unchecked ⇒ `uncompleteTask`); Master has none, since a template task cannot be completed (D18-adjacent — `completeTask` no-ops outside Today). Setting the Today "active" item moved from the title tap to the colour mark dot (now a `<button>` with an enlarged invisible hit area), freeing the body for tap-to-edit. **Undo toasts:** delete, Clear, and Start New Day now apply immediately and raise a bottom-centre one-tap undo bar (`Toast`, 5s). Those three reducers drop or collapse data with no inverse (unlike complete↔uncomplete, see `undoComposition.test.ts`), so undo restores a full pre-action `AppState` snapshot captured in `App` — which the existing save/sync effect re-persists for free. This replaces Start New Day's modal confirm; delete and Clear gain their first safety net. Touch reorder, which the D39 `@media (hover:none)` block had left to the now-removed toolbar buttons, moves into the Today edit panel. — 2026-07-27 (user request)
